# 学院学生综合服务与党团管理平台项目详细介绍

## 一、项目简介

“学院学生综合服务与党团管理平台”是一套面向学院学生与管理老师的综合事务服务系统。项目希望将原本分散的通知查看、学生信息维护、党团流程管理、申请审批、知识库查询、模板下载等事务集中到统一平台中，降低学生获取信息和提交申请的门槛，同时提高老师在管理、审批和信息发布方面的效率。

本项目采用“双端协同”的建设思路：

- 学生端使用微信小程序，方便学生随时随地访问系统
- 管理端使用 Web 后台，方便老师和管理员完成内容维护与业务处理
- 服务端接口负责支撑双端之间的数据联动

从课程项目的角度看，这个系统不仅体现了完整的软件工程流程，也具备比较明确的真实业务场景，能够展示从需求分析、系统设计、开发实现到测试验证的一整套工程实践。

---

## 二、项目背景与问题来源

在学院日常事务中，学生通常会遇到以下问题：

- 通知来源分散，容易遗漏重要信息
- 各类证明、请假、党团事务往往依赖线下沟通，流程不透明
- 知识类问题缺少统一查询入口，常见问题重复咨询
- 模板、资料、制度文件不便集中获取

而对于老师或管理员来说，也存在明显痛点：

- 通知发布缺少统一管理和统计能力
- 学生数据维护和账号管理工作量大
- 申请审批流转不直观，记录不完整
- 党团流程进度难以同步到学生端

因此，我们尝试通过一个统一平台，把“学生服务端”和“管理端”打通，形成“发布-查看-反馈”“提交-审批-回看”这样的核心业务闭环。

---

## 三、项目目标

本项目的总体目标可以概括为以下四点：

### 1. 建立统一入口

将通知、申请、知识库、流程查询、模板下载等常用功能集中到一个系统中，减少学生在多个渠道之间来回切换。

### 2. 打通双端协同

通过 Web 管理端和微信小程序端协同工作，使管理员的操作能够同步反映到学生端，形成完整业务闭环。

### 3. 支撑核心业务流程

优先实现高频、核心、可演示的业务链路，例如：

- 通知发布与已读统计
- 申请提交与审批反馈
- 学生信息维护与账号使用
- 党团流程更新与进度查看
- 知识库维护与搜索

### 4. 体现软件工程过程

项目不只是功能演示，还强调：

- 模块化设计
- 团队协作
- 版本管理
- 测试验证
- 文档沉淀

## 四、目标用户与使用场景

### 1. 学生用户

学生主要通过微信小程序访问系统，典型使用场景包括：

- 查看学院通知和已读状态
- 查询党团流程与个人进度
- 提交证明申请、请假申请等事务
- 搜索政策知识库内容
- 下载模板和相关资料
- 查看个人信息与历史申请

### 2. 管理员/老师

管理员主要通过 Web 管理端使用系统，典型场景包括：

- 发布和维护通知
- 查看通知已读统计
- 维护学生信息与重置密码
- 处理学生申请审批
- 配置党团流程并更新学生进度
- 管理知识库条目
- 进行导入导出与查看操作日志

## 五、系统整体结构

本项目采用“三部分协同”的系统结构：

### 1. 学生端小程序

学生端基于原生微信小程序实现，承担用户访问入口的角色，主要功能包括：

- 登录
- 首页信息展示
- 通知中心
- 服务页功能入口
- 申请提交与查看
- 党团流程查看
- 知识库搜索
- 模板下载
- 个人中心

### 2. Web 管理端

管理端基于 Vue 3 + Element Plus 构建，主要功能包括：

- 管理员登录
- 通知管理
- 学生管理
- 审批工作台
- 党团流程配置
- 知识库管理
- 数据导入导出
- 操作日志查看

### 3. 服务端接口

服务端承担双端数据交互的桥梁作用，提供统一接口支持。目前课程演示环境主要采用本地/测试接口支撑联调，用于验证双端业务是否能够跑通。

## 六、核心功能模块

从当前版本来看，项目的主要功能可以分为以下几个模块：

### 1. 通知管理模块

这是当前项目中最完整、最典型的业务闭环之一。

主要能力包括：

- 管理端新建、编辑、删除通知
- 学生端查看通知列表与详情
- 学生阅读后更新已读状态
- 管理端查看通知的已读/未读统计

这个模块很好地体现了“管理端发布 -> 学生端接收 -> 管理端回看结果”的双端协同机制。

### 2. 申请审批模块

申请审批模块支撑学生提交事务申请和管理员审核处理。

主要能力包括：

- 小程序端填写并提交申请
- Web 管理端查看待审批事项
- 管理员执行通过、驳回或要求补交
- 学生端查看审批状态和审批意见

这个模块体现了“提交 -> 审批 -> 反馈”的完整业务流程。

### 3. 学生信息管理模块

管理端可维护学生基础信息，并为学生生成或重置登录账号。

主要能力包括：

- 学生信息新增、编辑、删除
- 按年级、专业、政治面貌筛选
- 密码重置
- 小程序端基于学生账号登录并查看个人信息

### 4. 党团流程模块

该模块面向党团事务场景，用于展示和维护学生的流程阶段。

主要能力包括：

- 管理端配置或调整流程阶段
- 管理端更新学生当前进度
- 小程序端查看入党/入团等流程当前阶段

### 5. 知识库模块

该模块用于沉淀常见政策、制度和答疑内容。

主要能力包括：

- 管理端新增和维护知识库条目
- 小程序端按关键词搜索知识内容
- 查看知识详情

### 6. 文件与模板模块

该模块用于支持模板、资料和文件的上传下载。

主要能力包括：

- 管理端上传模板文件
- 小程序端查看模板并下载
- 支持作为申请、知识库等功能的辅助资源

### 7. 导入导出模块

该模块面向管理效率，支持批量数据处理。

主要能力包括：

- 下载学生信息模板
- CSV 学生信息导入
- 导入后自动形成学生数据
- 为后续批量管理提供基础支撑

## 七、核心业务闭环

本项目汇报最值得强调的不是“做了多少页面”，而是“跑通了多少业务闭环”。目前最有代表性的三条闭环如下：

### 1. 通知发布闭环

- 管理员在 Web 管理端发布通知
- 学生在小程序通知页看到新通知
- 学生查看详情后状态变为已读
- 管理员回到管理端查看已读统计

这个闭环证明了系统具备真实的数据流转能力，而不是静态页面展示。

### 2. 申请审批闭环

- 学生在小程序提交申请
- 管理员在 Web 审批工作台查看待办
- 管理员审批后，状态被更新
- 学生在小程序查看审批结果与意见

这个闭环证明系统能够支持“提交-审核-反馈”的典型事务流程。

### 3. 信息维护与服务支撑闭环

- 管理员维护学生信息、党团流程、知识条目
- 学生通过小程序登录、查看、搜索、使用这些信息

这个闭环体现的是平台作为“综合服务平台”的基础支撑能力。

## 八、技术路线与实现思路

项目在当前版本中的技术路线主要包括：

### 1. 小程序端

- 原生微信小程序
- TypeScript + Less
- 页面与组件化实现

### 2. Web 管理端

- Vue 3
- Vue Router
- Element Plus
- Axios
- Vite

### 3. 服务端与联调方式

- 课程演示环境下，当前版本主要依赖测试/本地接口支撑双端联调
- 后续可进一步扩展到更完整的正式后端架构

### 4. 实现策略

我们在实现时采取“核心业务优先、闭环优先”的策略：

- 先保证通知、审批、学生信息、流程等核心功能可跑通
- 再逐步扩展知识库、导入导出、文件管理等支撑能力
- 在功能完整性和可演示性之间做平衡

虽然当前版本已经具备较完整的演示能力，但仍存在一些不足：

- 部分模块仍偏演示版，真实业务深度还不够

### 后续改进方向

- 完善正式后端与数据库支撑
- 提升权限控制与数据安全能力
- 强化导入导出、文件管理等管理端能力
- 增加更多自动化测试与异常处理
- 优化小程序交互体验和页面表现
