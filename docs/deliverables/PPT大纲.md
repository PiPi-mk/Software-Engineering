# 学院学生综合服务与党团管理平台期末汇报 PPT 大纲

## 使用说明

这份大纲用于生成期末汇报 PPT，汇报主线采用“核心功能闭环 + 测试验证”方式展开。整体建议控制在 `8-12 分钟`，推荐 `10 页左右`，兼顾老师给出的课程大纲和项目本身的展示效果。

汇报重点建议放在：

- 项目整体目标与系统结构
- 通知闭环、申请审批闭环等核心功能
- 功能满足性与测试结果
- 团队协作、工具使用和问题总结

---

## 第 1 页：封面

### 标题建议

`学院学生综合服务与党团管理平台`

### 页面内容

- 项目名称
- 团队成员
- 汇报人
- 日期

### 页面作用

用于建立项目身份信息，开场简洁清晰。

### 视觉建议

- 背景简洁、正式
- 可加入三端图标：小程序端、Web 管理端、服务端

### 讲述重点

- 项目名称
- 项目面向的主要对象
- 本次汇报将围绕功能闭环、设计实现和测试验证展开

## 第 2 页：项目概述

### 标题建议

`项目概述`

### 页面内容

- 项目背景：
  - 学生事务分散、通知获取不统一
  - 审批流程效率低、流程透明度不足
  - 知识查询和资料获取入口不集中
- 目标用户：
  - 学生
  - 管理员/老师
- 项目目标：
  - 构建统一的学生事务服务平台
  - 打通学生端与管理端
  - 支撑通知、申请、流程、知识库等业务

### 页面作用

说明“为什么要做这个项目”以及“项目服务谁、解决什么问题”。

### 视觉建议

- 左侧写“问题”
- 右侧写“解决方案”
- 底部用 3 个关键词概括：`统一入口`、`双端联动`、`业务闭环`

### 讲述重点

- 项目的问题来源是真实的学院事务场景
- 系统不是单一页面，而是一个综合服务平台

## 第 4 页：核心功能闭环一：通知管理

### 标题建议

`核心功能闭环一：通知发布与已读统计`

### 页面内容

- 管理端发布通知
- 学生端查看通知列表与详情
- 学生阅读后形成已读记录
- 管理端查看通知已读/未读统计

### 页面作用

展示项目最清晰、最容易理解的核心业务闭环。

### 视觉建议

流程图：

`Web 发布通知 -> 小程序查看通知 -> 学生已读 -> Web 查看统计`

可搭配 2 到 3 张截图：

- Web 通知管理页
- 小程序通知页
- Web 通知统计页

### 讲述重点

- 这是一个典型的双端联动闭环
- 体现了从发布到结果回看的完整流程

## 汇报主线提醒

整场汇报尽量围绕以下 4 个问题展开：

1. 我们为什么做这个项目
2. 我们做了哪两个端，如何协同
3. 我们跑通了哪些核心业务闭环
4. 我们如何验证这些功能是有效的

这样老师会更容易抓住你们项目的重点，也能更容易看出你们的工程思路是完整的。

## 制作 PPT 时的注意事项

### 1. 不要堆字

每一页尽量控制在：

- 一个清晰标题
- 3 到 5 个重点 bullet
- 1 张结构图或 2 到 3 张截图

### 2. 优先放“变化型截图”

最适合放的不是单张静态页面，而是能体现“前后变化”的页面，例如：

- 发布前后
- 审批前后
- 更新前后
- 已读前后

### 3. 少讲实现细节，多讲业务价值

PPT 里不要过多写代码细节，应重点强调：

- 功能怎么跑通
- 用户怎么使用
- 系统怎么协同
- 测试怎么验证

### 4. 与测试文档保持一致

PPT 中提到的核心测试场景、通过情况、结论，建议与你们最终提交的测试文档保持一致，避免答辩时口径不统一。
