## 当前可运行内容：demoApp（微信小程序 Demo + 本地 API）

说明文档：[demoApp/README.md](file:///workspace/demoApp/README.md)

### 1) 启动本地服务端

在仓库根目录执行：

```bash
node demoApp/server/index.js
```

服务默认监听 `3000` 端口，接口清单见 [demoApp/README.md](file:///workspace/demoApp/README.md#L28-L41)。

### 2) 在微信开发者工具导入并运行

- 导入目录选择：`demoApp/`（该目录下包含 `app.js/app.json`）
- 登录后进入待办页，增删查会请求本地 `http://localhost:3000`
- Network 练习：登录页点击入口进入 `pages/network-demo`，对照成功/失败请求观察 Network 面板

### 3) 常见调试点

- 若待办页请求失败：优先确认服务端是否已启动、端口是否为 3000、以及本机是否允许访问 `localhost`
- 若外网请求（httpbin）不可用：开发者工具配置中可绕过合法域名校验（`urlCheck: false`），见 [demoApp/project.config.json](file:///workspace/demoApp/project.config.json#L2-L6)

## 目标系统的建议开发与集成方式（按仓库文档）

来源：[四人分工与整体流程计划.md](file:///workspace/四人分工与整体流程计划.md)

### 分支策略

推荐约定（文档原文）：见 [四人分工与整体流程计划.md](file:///workspace/四人分工与整体流程计划.md#L136-L138)

- `main`：始终可运行（用于里程碑演示与交付）
- `dev`：集成分支（每两天至少一次集成日）
- `feature-xxx`：个人功能分支（完成后合并到 dev）

### 推进节奏

推荐节奏：见 [四人分工与整体流程计划.md](file:///workspace/四人分工与整体流程计划.md#L28-L32)

- 每天 10 分钟站会：同步进度与卡点
- 每两天一次集成日：确保主干可跑、减少最后集成爆炸
- 每周一个可演示版本：至少跑通 1 条闭环

### 闭环优先的交付顺序

建议顺序：见 [四人分工与整体流程计划.md](file:///workspace/四人分工与整体流程计划.md#L33-L39)

1. 登录绑定 + 基础用户/角色
2. 通知：管理端发布 → 学生端接收 → 已读统计
3. 党团流程：流程配置 → 学生端展示 → 个人进度更新
4. 证明/申请：提交 → 多级审批 → 结果文件生成/下载
5. 导入导出：学生导入、审批记录导出、通知导入
6. 知识库：条目维护与学生搜索
