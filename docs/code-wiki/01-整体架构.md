# 01 整体架构

## 架构总览

整体是典型的「小程序客户端 + 本地服务端」的教学型双端结构：

- 客户端（微信小程序）：负责界面、交互与发起请求。
- 服务端（本地 Node.js）：负责待办列表的增删查与存储（内存态），用于演示“同一 API 被小程序与 Postman 共用”。

## 客户端架构（小程序）

### 启动与导航（等价路由）

- 页面注册（“路由表”）：由 [demoApp/app.json](file:///workspace/demoApp/app.json#L1-L6) 的 `pages` 数组决定。
- 启动入口：小程序启动会执行 [demoApp/app.js](file:///workspace/demoApp/app.js#L3-L14) 的 `App({ onLaunch })`。
  - 若检测到 `session:v1` 存在且包含 `nickname`，则 `wx.reLaunch` 直接进入待办页 `/pages/todos/todos`。
- 页面级导航：
  - 登录页进入 Network 练习页：`wx.navigateTo('/pages/network-demo/network-demo')`，见 [login.js](file:///workspace/demoApp/pages/login/login.js#L32-L34)。
  - 待办页校验会话失败时强制回到登录页：`wx.reLaunch('/pages/login/login')`，见 [todos.js](file:///workspace/demoApp/pages/todos/todos.js#L32-L37)。

### 状态管理（Page data + Storage）

项目没有引入外部状态管理库，状态分两层：

1. 页面内状态：通过 `Page({ data, setData })` 管理，例如：
   - 登录页：`nickname/password/loading`，见 [login.js](file:///workspace/demoApp/pages/login/login.js#L17-L22)。
   - 待办页：`nickname/newText/todos/serverApiError/loading`，见 [todos.js](file:///workspace/demoApp/pages/todos/todos.js#L23-L30)。
2. 跨页面/持久化状态：通过 `wx.*StorageSync` 存储键值对：
   - `users:v1`：用户表（昵称 -> 密码 hash）
   - `session:v1`：当前会话（昵称、登录时间）
   - `todos:v1:<nickname>`：旧版本“仅本地存储”的待办（现用于一次性迁移）
   - 相关封装与 key 约定在 [storage.js](file:///workspace/demoApp/utils/storage.js#L1-L77)。

### 数据流（待办为例）

待办页以服务端为唯一数据源，流程如下：

1. 页面展示（onShow）：读取会话，拿到 `nickname` 后拉取服务端列表，见 [todos.js](file:///workspace/demoApp/pages/todos/todos.js#L32-L43)。
2. 拉取列表（GET /todo/list）：
   - 成功返回 `data` 数组后，格式化 `createdAt` 并更新 UI，见 [applyServerList](file:///workspace/demoApp/pages/todos/todos.js#L45-L51)。
3. “旧本地待办”迁移：
   - 若服务端列表为空且 `todos:v1:<nickname>` 有旧数据，则自动执行 `POST /todo/sync` 全量覆盖服务端，然后清空本地旧键，见 [fetchTodoList](file:///workspace/demoApp/pages/todos/todos.js#L82-L108)。
4. 新增/删除：
   - 新增：`POST /todo/add`，见 [onAdd](file:///workspace/demoApp/pages/todos/todos.js#L125-L157)。
   - 删除：`DELETE /todo/item`，见 [onDelete](file:///workspace/demoApp/pages/todos/todos.js#L159-L188)。

## 服务端架构（Node.js 待办 API）

服务端位于 [demoApp/server/index.js](file:///workspace/demoApp/server/index.js)，特点：

- 基于 Node.js 原生 `http` 模块，无第三方框架依赖。
- 内存数据结构：`todoStore: Record<string, TodoItem[]>`，按 `nickname` 隔离。
- 请求处理要点
  - CORS：统一设置 `Access-Control-Allow-*`，见 [cors](file:///workspace/demoApp/server/index.js#L15-L19)。
  - JSON 响应：统一 `json(res, status, obj)`，见 [json](file:///workspace/demoApp/server/index.js#L21-L26)。
  - JSON body 解析：`readJsonBody(req)` 收集 chunks 并 `JSON.parse`，见 [readJsonBody](file:///workspace/demoApp/server/index.js#L44-L62)。
  - 参数校验：对 `/todo/*` 接口要求 query `nickname`，缺失返回 400，见 [index.js](file:///workspace/demoApp/server/index.js#L75-L88)。

## 外部网络请求（教学用）

项目使用 `httpbin.org` 提供可观察的请求回显，用于 Network 面板教学：

- 登录页演示请求：`POST https://httpbin.org/post`，见 [login.js](file:///workspace/demoApp/pages/login/login.js#L12-L110)。
- Network 专项页：
  - 成功：`GET https://httpbin.org/get`
  - 失败：请求 `.invalid` 保留域名触发 fail
  - 见 [network-demo.js](file:///workspace/demoApp/pages/network-demo/network-demo.js#L1-L56)。
