# 01 整体架构

## 总体形态（按需求定义）

目标系统由四个主要部分组成（见 [需求文档-小组需求说明V1.md](file:///workspace/需求文档-小组需求说明V1.md#L14-L19)）：

- 学生端：微信小程序（需求建议可用 uni-app 以复用 Vue 语法，见 [四人分工与整体流程计划.md](file:///workspace/四人分工与整体流程计划.md#L9-L13)）
- 管理端：PC Web 管理后台（Vue 3 + Element Plus，见 [四人分工与整体流程计划.md](file:///workspace/四人分工与整体流程计划.md#L9-L12)）
- 后端服务：统一 API、权限控制、文件处理、定时任务
- 数据库：人大金仓 Kingbase（按 PostgreSQL 方式连接与建模）

## 逻辑分层（推荐）

为支撑“可配置流程 + 电子审批 + 导入导出”的长期演进，后端建议采用清晰的分层结构：

- 接口层（HTTP Controller）
  - 统一返回格式（`code/message/data`），见协作约定 [四人分工与整体流程计划.md](file:///workspace/四人分工与整体流程计划.md#L136-L139)
  - 权限鉴别与参数校验
- 领域/业务层（Service）
  - 通知发布与阅读统计、流程与进度、审批流转、知识库检索、导入导出任务
- 数据访问层（Repository/DAO）
  - 访问 Kingbase（表结构见“关键领域对象”一节）
- 基础设施层（Infra）
  - 文件存储（上传/下载/归档）
  - 定时任务（提醒规则触发、任务状态轮询）
  - 日志与审计（关键操作留痕）

## 端到端交互（核心链路）

### 登录与身份绑定

需求流程见 [需求文档-小组需求说明V1.md](file:///workspace/需求文档-小组需求说明V1.md#L45-L50)：

- 学生端使用小程序登录能力获取临时凭证
- 后端完成身份匹配/绑定（学号、姓名等来自导入或后台维护）
- 成功后发放 token（学生端与管理端均需鉴权）

### 通知发布与接收

需求流程见 [需求文档-小组需求说明V1.md](file:///workspace/需求文档-小组需求说明V1.md#L51-L56)：

- 管理端创建通知（标题、正文、附件、标签、人群规则）
- 后端保存通知与目标人群规则，生成发送记录
- 学生端通知中心拉取列表与详情，阅读后上报已读
- 后端聚合统计（已读数、阅读时间等）

### 党团流程与个人进度

需求流程见 [需求文档-小组需求说明V1.md](file:///workspace/需求文档-小组需求说明V1.md#L57-L63)：

- 管理端配置流程阶段（名称、材料、时限、负责角色等）
- 学生端展示全流程与阶段说明
- 管理端更新学生当前阶段/动作记录
- 后端依据提醒规则触发站内提醒（可配置提醒对象与时间）

### 证明/申请审批

需求流程见 [需求文档-小组需求说明V1.md](file:///workspace/需求文档-小组需求说明V1.md#L64-L69)：

- 学生端提交申请（表单字段 + 附件）
- 后端创建申请单并流转到待审批队列
- 管理端审批工作台完成多级审批（通过/驳回/补交），过程留痕
- 通过后生成结果文件（PDF/系统文件），提供学生下载与管理端归档导出
