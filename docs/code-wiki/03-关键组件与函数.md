# 03 关键组件与函数

本项目没有“类（class）”定义，关键逻辑主要以“页面对象（Page）方法 + 工具函数 + 服务端函数”的形式存在。

## 小程序全局入口

### App.onLaunch

文件：[demoApp/app.js](file:///workspace/demoApp/app.js#L3-L14)

作用：

- 启动时读取会话 `session:v1`（通过 [getSession](file:///workspace/demoApp/utils/storage.js#L42-L44)）。
- 若已登录则直接 `wx.reLaunch` 到待办页，绕过登录页。

## 登录页（pages/login）

文件：[demoApp/pages/login/login.js](file:///workspace/demoApp/pages/login/login.js)

### normalizeNickname

定义：[login.js](file:///workspace/demoApp/pages/login/login.js#L8-L10)

作用：

- 对昵称做 `trim` 规范化，确保同一用户昵称唯一性更稳定。

### onLogin（登录主流程）

定义：[login.js](file:///workspace/demoApp/pages/login/login.js#L64-L111)

流程：

1. 校验输入（昵称/密码非空）。
2. 触发 Network 教学请求（`wx.request` POST 到 `https://httpbin.org/post`）。
3. 无论请求成功与否，都在 `complete` 回调进入本地登录逻辑（[doLocalLogin](file:///workspace/demoApp/pages/login/login.js#L36-L62)）。

关键点：

- 为了让 Network 面板更稳定展示请求，页面跳转使用了延迟 `RELAUNCH_DELAY_MS`，见 [login.js](file:///workspace/demoApp/pages/login/login.js#L14-L15)。

### doLocalLogin（本地注册/校验 + 写会话）

定义：[login.js](file:///workspace/demoApp/pages/login/login.js#L36-L62)

行为规则：

- 若昵称存在：校验 `passwordHash`，不一致提示“密码错误”。
- 若昵称不存在：自动注册（写入 `users:v1`）。
- 写入会话 `session:v1` 后跳转到待办页 `/pages/todos/todos`。

依赖：

- 用户表：`loadUsers/saveUsers`，见 [storage.js](file:///workspace/demoApp/utils/storage.js#L34-L40)
- 密码 hash：`hashPassword`，见 [storage.js](file:///workspace/demoApp/utils/storage.js#L24-L32)
- 会话写入：`setSession`，见 [storage.js](file:///workspace/demoApp/utils/storage.js#L46-L48)

## 待办页（pages/todos）

文件：[demoApp/pages/todos/todos.js](file:///workspace/demoApp/pages/todos/todos.js)

### onShow（会话校验 + 首次拉取）

定义：[todos.js](file:///workspace/demoApp/pages/todos/todos.js#L32-L43)

要点：

- 若未登录，使用 `wx.reLaunch` 强制回登录页。
- 先 `setData({ nickname })` 再调用 `fetchTodoList(nickname)`，避免异步 setData 导致昵称为空时请求被短路（文件内有说明）。

### fetchTodoList（服务端列表拉取 + 旧数据迁移）

定义：[todos.js](file:///workspace/demoApp/pages/todos/todos.js#L53-L119)

职责：

- 以 `GET /todo/list` 拉取服务端列表作为唯一数据源。
- 当服务端列表为空且本地存在旧待办（`todos:v1:<nickname>`）：
  - `POST /todo/sync` 将旧数据全量覆盖到服务端
  - 成功后清空本地旧键

迁移逻辑入口位置：

- 本地旧数据读取：[loadTodos](file:///workspace/demoApp/utils/storage.js#L60-L62)
- 迁移请求触发：[todos.js](file:///workspace/demoApp/pages/todos/todos.js#L82-L108)

### onAdd / onDelete（CRUD）

- 新增：[onAdd](file:///workspace/demoApp/pages/todos/todos.js#L125-L157)
  - `POST /todo/add`，body `{ text }`，成功后直接用服务端返回的完整列表刷新 UI。
- 删除：[onDelete](file:///workspace/demoApp/pages/todos/todos.js#L159-L188)
  - `DELETE /todo/item?nickname=&id=`，成功后用服务端返回列表刷新 UI。

### onLogout（退出）

定义：[todos.js](file:///workspace/demoApp/pages/todos/todos.js#L190-L201)

行为：

- 弹窗确认后调用 [clearSession](file:///workspace/demoApp/utils/storage.js#L50-L54) 清理会话，并跳回登录页。

## 服务端（server/index.js）

文件：[demoApp/server/index.js](file:///workspace/demoApp/server/index.js)

### 路由与数据结构

核心：

- `todoStore`：按 nickname 分桶的数组列表，见 [index.js](file:///workspace/demoApp/server/index.js#L12-L42)
- `getList(nickname)`：确保桶存在并返回引用，见 [getList](file:///workspace/demoApp/server/index.js#L37-L42)

### readJsonBody（请求体解析）

定义：[readJsonBody](file:///workspace/demoApp/server/index.js#L44-L62)

行为：

- 收集 body chunks，空 body 解析为 `{}`，非空则尝试 `JSON.parse`，解析失败返回 400。

### API 列表

定义位置：服务端顶端注释与分支处理逻辑，见 [index.js](file:///workspace/demoApp/server/index.js#L1-L165)

- `GET /todo/list?nickname=`：返回该用户完整列表
- `POST /todo/add?nickname=`：新增一条，返回最新完整列表
- `POST /todo/sync?nickname=`：用 body.items 全量覆盖该用户列表，返回最新完整列表
- `DELETE /todo/item?nickname=&id=`：删除一条，返回最新完整列表
