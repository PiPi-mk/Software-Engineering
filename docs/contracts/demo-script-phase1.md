# 演示/验收脚本：一期闭环1（全员通知）

目标：在同一套环境里跑通“管理端发布通知 → 学生端接收并已读 → 管理端查看统计”。

## 前置条件

- 后端服务可用（`/api/health` 返回正常）
- 已导入一期测试账号（见 [test-data.md](./test-data.md)）
- 一期范围：全员通知，不做按标签/人群规则筛选

## 角色与账号

- 管理员（管理端）：`admin / admin123`
- 学生 A（学生端）：`student1 / student123`
- 学生 B（学生端）：`student2 / student123`

## 验收步骤（按顺序执行）

### 1) 管理员登录

1. 打开管理端登录页
2. 使用管理员账号登录
3. 验收点：
   - 登录成功后前端持有 token
   - 调用 `/api/auth/me` 返回 role=admin

### 2) 管理员发布一条通知（全员）

1. 进入“通知管理”页面
2. 新建通知并发布（标题、正文必填）
3. 验收点：
   - 调用 `POST /api/notices` 成功，返回 `id`
   - 通知列表顶部出现新通知（发布时间正确）

### 3) 学生 A 登录并拉取通知列表

1. 打开学生端登录页
2. 使用学生 A 登录
3. 进入通知中心
4. 验收点：
   - 调用 `GET /api/notices` 返回列表包含刚发布的通知
   - 新通知的 `read=false`

### 4) 学生 A 查看详情并标记已读

1. 学生 A 打开通知详情页（调用 `GET /api/notices/:id`）
2. 点击“标记已读”（或进入详情后显式触发“已读上报”）
3. 验收点：
   - 调用 `POST /api/notices/:id/read` 成功返回 `readAt`
   - 返回通知列表后，该条通知 `read=true`
   - 重复点击“已读”不报错（幂等）

### 5) 学生 B 登录验证“未读”

1. 学生 B 登录并进入通知中心
2. 验收点：
   - 同一条通知 `read=false`

### 6) 管理员查看统计

1. 管理员打开该通知的统计面板
2. 验收点：
   - 调用 `GET /api/notices/:id/stats` 返回 `{ total, readCount, unreadCount }`
   - 预期：`total=2`，`readCount=1`，`unreadCount=1`

## 通过标准

- 全流程无报错
- 权限不串：学生无法访问 stats，管理员无法调用 read
- 已读统计与实际学生行为一致
