# 集成日检查清单（一期闭环1）

目标：每次合并到 `dev` 前都能快速判断“是否可跑、是否可演示、是否权限不串”。

## 1. 分支与提交

- 变更在 `feature/*` 分支完成，并指向明确的闭环1验收点
- 合并到 `dev` 前已自测通过本清单

## 2. 后端可用性（最小）

- 后端能启动且端口明确（建议 3000）
- `GET /api/health` 返回成功
- 接口返回结构始终为 `{ code, message, data }`（见 [errors.md](./errors.md)）

## 3. 鉴权与权限

- 未带 token 调用受保护接口返回 `40101`
- 管理员可发布通知、可看统计
- 学生可拉取列表/详情、可标记已读
- 学生访问 `/stats` 返回 `40301`
- 管理员访问 `/read` 返回 `40301`

## 4. 闭环1验收

按 [demo-script-phase1.md](./demo-script-phase1.md) 走一遍：

- 发布 → 学生A列表显示未读 → 学生A已读 → 学生B仍未读 → 管理端统计正确

## 5. 回归点（防止踩坑）

- “已读上报”幂等：重复调用不报错
- 列表排序：最新通知在前（以 publishedAt 降序）
- 错误信息可读：`message` 能定位是参数问题还是权限问题
