# 错误码与返回规范

## 统一返回格式

除文件下载等特殊接口外，所有接口均返回 JSON：

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

约定：

- `code = 0` 表示成功；非 0 表示业务错误或鉴权错误。
- `message` 面向用户或联调人员，可读、可定位。
- `data` 为业务数据；失败时可为空对象或 `null`（保持结构稳定）。

## HTTP 状态码约定

- `200`：业务成功；或业务失败但需要返回业务错误码（推荐：业务失败也用 200，靠 `code` 区分，减少前端分支）。
- `400`：请求参数无法解析（例如 JSON 解析失败）。
- `404`：路由不存在（开发期可见；正式环境可统一为 404）。
- `500`：未捕获异常（应尽量减少，统一错误处理中间件兜底）。

## 错误码（v1）

| code | 含义 | 推荐 HTTP | message 示例 |
|------|------|----------|--------------|
| 0 | 成功 | 200 | ok |
| 40001 | 参数缺失/格式错误 | 200/400 | 缺少字段 title |
| 40101 | 未登录/Token 无效 | 200 | 未登录 |
| 40301 | 无权限 | 200 | 权限不足 |
| 40401 | 资源不存在 | 200 | 通知不存在 |
| 40901 | 冲突（重复操作） | 200 | 已读记录已存在 |
| 50001 | 服务端内部错误 | 500 | internal error |

## 错误返回示例

```json
{
  "code": 40101,
  "message": "未登录",
  "data": null
}
```
